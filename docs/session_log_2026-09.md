# 작업 기록 (2026-09) — 버그 수정 + 실측 데이터 검증

이 문서는 이번 세션에서 `optical-metrology-fitter`에 가한 모든 변경을 **이유 → 조치 → 실제 실행 결과** 순으로 기록한다. 코드 자체의 docstring/주석과 별개로, "왜 이렇게 바꿨고 실행해보니 뭐가 나왔는지"를 남기기 위한 문서.

## 1. `omf/fitter.py` — coarse_scan 중복 계산 제거

**이유**
`FilmModel.coarse_scan()`이 두께 그리드(`d_grid`)의 점마다 `reflectance()` → `build_n_list()`를 매번 새로 호출하고 있었다. 그런데 `build_n_list()`가 만드는 굴절률 배열은 파장에만 의존하지 두께(`d`)에는 의존하지 않는다. 즉 그리드 점이 3000개면 SiO2 Sellmeier / Si 보간 계산을 3000번 반복하는 셈이었다. 이 프로젝트가 "벡터화로 196배 빨라졌다"를 핵심 성과로 내세우는데, 정작 역문제의 핵심부(pre-scan)에 이런 중복이 남아있던 게 문제.

**조치**
- `reflectance()`를 얇은 래퍼로 남기고, 실제 계산 로직을 `_reflectance_with_n(params, n_list, lam, theta_rad)`로 분리.
- `coarse_scan()`과 `fit()`이 `build_n_list()`를 각각 한 번씩만 호출하고, 이후 grid 스캔·Jacobian 평가·잔차 계산에 그 `n_list`를 재사용하도록 변경.
- 공개 API(`reflectance()`, `fit()`, `coarse_scan()`의 시그니처)는 그대로 유지 — 내부 구현만 바뀜.

**실행 결과 (실측)**
- `d_grid=3000`, `251` 파장 기준 coarse scan 단독 벤치마크: **1594ms → 1323ms (1.2배)**.
  (SiO2/Si 굴절률 계산이 `coh_tmm`의 행렬곱보다 상대적으로 가벼워서 개선폭이 크진 않았음 — 정직하게 기록.)
- 정확도 검증: `d_true=217.3nm`에 노이즈(σ=2e-4)를 준 합성 스펙트럼을 피팅 → **d = 217.2925 ± 0.0044 nm** (README에 보고된 기존 결과와 동일 오더로 일치). 수정 전후 결과값 자체는 변화 없음 — 순수 성능 개선.

## 2. `tests/test_core.py` — 검증 스위트 조기 중단 버그

**이유**
`check()` 함수가 실패 시 `assert`를 던지는데, 34개 체크를 순서대로 실행하는 `main()`이 이 예외를 잡지 않았다. 즉 34개 중 하나라도 실패하면 그 자리에서 스크립트가 죽어버려서, 이후 체크들은 물론 마지막의 "N / 34 passed" 집계 코드조차 실행되지 않았다. `_RESULTS` 리스트로 전체 결과를 모아 리포트하겠다는 설계 의도와 실제 동작이 어긋나 있었음.

**조치**
- `check()`는 그대로 두되(= `assert` 유지, `pytest tests/test_core.py`로 개별 테스트 함수 단위 실패를 잡을 수 있게), `main()`에서 각 테스트 함수 호출을 `run(test_fn)`으로 감쌈.
- `run()`은 `AssertionError`만 잡아서 무시하고 다음 테스트로 진행 — 배치 전체가 죽지 않게 함.

**실행 결과 (실측)**
- 별도 스크립트로 일부러 체크 하나를 실패시켜 재현: 수정 전 로직이면 여기서 전체가 죽었을 상황을, `run()`이 실패를 기록만 하고 다음 체크(`this must still run`)로 넘어가는 것을 확인.
  ```
  [FAIL] deliberately broken check   proof-of-concept failure
  [PASS] this must still run
  ```
- 실제 스위트 실행: **29 / 29 통과** (Tier C는 참조 패키지 `tmm` 미설치로 스킵 — README에 명시된 정상적인 skip 경로).

## 3. 실측(real-world) 데이터로 피팅 — 타원편광(ellipsometry) 지원 신규 추가

**이유**
사용자 질문: "실제 웨이퍼 값으로 계측해볼 수 없나?" → 이 프로젝트가 지금까지 낸 모든 숫자(4pm, 1.3nm 등)는 전부 합성 데이터였다는 게 스스로 인정한 최대 한계였음. 순수 반사율(R) 형태의 공개 실측 CSV는 찾지 못했지만, GitHub `refnx/refellips` 저장소에 **실제 J.A. Woollam WVASE 타원편광계로 측정한 진짜 데이터**(Psi, Delta)가 있었음. 다만 이 프로젝트의 기존 `FilmModel`은 반사율 R만 피팅하도록 짜여 있어서, 이 실측 데이터를 쓰려면 확장이 필요했음.

**조치 — 추가된 것**

| 파일 | 내용 |
|---|---|
| `omf/core.py` | `psi_delta(n_list, d_list, th_0, lam_vac)` 함수 추가. `r_s`, `r_p`를 각각 계산해 `rho = r_p/r_s = tan(Psi)·exp(iΔ)`로 Psi/Delta 산출. `R`/`T` 전용이던 기존 `coh_tmm`을 그대로 재사용(같은 branch rule, 같은 Fresnel 계수). |
| `omf/materials.py` | 실측 PNIPAM(건조 상태, refellips 제공 테이블), 실측 물 굴절률 테이블 로더 추가 (`n_pnipam_swollen`*, `n_water`). *이름은 나중에 오해였음이 드러남 — 4번 항목 참조. |
| `data/PNIPAM_swollen.csv`, `data/water.csv` | refnx/refellips의 `materials/pnipam.csv`, `materials/water.csv`를 이 프로젝트의 nm 단위 CSV 포맷으로 변환해 저장. MIT 라이선스, 출처 주석 포함. |
| `data/WVASE_2nmSiO2_PNIPAM_water_real.dat` | **실제 측정 데이터 원본.** PNIPAM 브러시(건조 시 공칭 ~100nm)가 2nm 자연산화막(SiO2)/Si 위에서 15°C 물속에 잠긴 상태로, 65° 고정각·400–800nm 11개 파장에서 측정된 Psi/Delta. 출처: `refnx/refellips`, `demos/WVASE_example_2nmSiO2_100nmPNIPAM_MultiWavelength_Water.dat` (MIT). **합성 데이터 아님.** |
| `omf/fitter.py` | `EllipsometryModel` 클래스 신규 추가. `FilmModel`과 동일한 구조(coarse-scan → local refine, `fit_dn` 지원)로 R 대신 (Psi, Delta) 쌍을 피팅. |
| `omf/__init__.py` | 위 신규 심볼들(`psi_delta`, `n_pnipam_swollen`, `n_water`, `EllipsometryModel`) 패키지 공개 API에 등록. |
| `scripts/exp05_real_data_ellipsometry.py` | 위 실측 데이터를 로드해서 실제로 피팅을 실행하는 스크립트. |

**부수적으로 발견/해결한 이슈**
- `coh_tmm`은 입사매질(여기선 물)이 정확히 무손실(실수 굴절률)이어야 한다는 물리적 제약을 갖고 있음(`R`/`T`가 플럭스비로 정의되려면 입사파 자체가 감쇠하면 안 되므로). 물의 흡수계수 k는 400–800nm에서 1e-9~4e-7 수준으로 무시 가능하지만 정확히 0은 아니라서 이 체크에 걸림 → 스크립트 안에서 물의 실수부만 쓰는 `n_water_incident()` 래퍼로 우회 (라이브러리 본체는 건드리지 않음, 물리적으로 정당화된 근사임을 주석에 명시).

## 4. 실제 피팅 실행 결과

스택: `water / PNIPAM(자유 두께) / SiO2(2nm, 고정) / Si`, 65° 고정각, 11개 파장(400–800nm).

### 시도 1 — PNIPAM을 건조 상태 테이블 그대로 사용 (두께만 자유 파라미터)

| 항목 | 값 |
|---|---|
| 피팅 결과 | d = 228.55 ± 6.83 nm |
| 잔차 RMS | **18.35°** |

굴절률 확인 결과 `pnipam.csv`(내가 "PNIPAM_swollen"이라 이름 붙였던 테이블)는 실제로는 **건조(dry) 상태**의 값(n ≈ 1.50–1.52, 400–800nm)이었다. 물속에서 팽윤된 브러시는 물을 잔뜩 머금어 유효 굴절률이 물(n ≈ 1.33–1.34)에 훨씬 가까워야 하는데, 그 반대로 건조 값을 그대로 쓴 것. 결과적으로 Psi의 파장 의존 추세가 **실측과 정반대**로 나왔다 (측정: 파장↑→Psi↓, 모델: 파장↑→Psi↑). 잔차 18.35°는 명백히 실패한 피팅.

### 시도 2 — 굴절률 오프셋(`dn`)을 두 번째 자유 파라미터로 추가

`EllipsometryModel`에 `FilmModel.fit_dn`과 동일한 메커니즘을 이식(§3). 두께와 `dn`(건조 테이블 대비 보정값)을 동시에 피팅.

| 항목 | as measured | delta+180 (부호 규약 반대 가정) |
|---|---|---|
| 두께 | 6.19 ± 32.84 nm | 642.67 ± 250.18 nm |
| dn | **-0.5000** (탐색범위 하한에 붙음) | -0.2897 |
| 잔차 RMS | **4.40°** | 22.81° |

`r_p`의 부호가 규약 문제라는 점(`core.py` docstring)을 감안해 Δ를 180° 뒤집은 가설도 같이 검증했는데, "측정된 그대로"가 더 나은 잔차를 줬다 — 이 시료/장비에 한해서는 이 프로젝트의 기존 부호 규약(Byrnes convention)이 맞는 쪽이라는 뜻.

RMS 4.40°는 시도 1보다는 훨씬 낫지만, **`dn`이 탐색 허용범위(-0.5 ~ +0.5)의 경계값에 정확히 붙어버렸다.** 이게 문제인 이유:
- 유효 굴절률이 n ≈ **1.00**(진공 수준)까지 밀림 — 물(n=1.33)보다도 낮은, 물리적으로 불가능한 값.
- 피팅된 두께(6.19nm)가 건조 상태 공칭값(100nm)보다 오히려 **얇게** 나옴 — "팽윤되면 더 두꺼워져야 한다"는 물리적 기대와 정반대.

**결론**: 단일 균일층(homogeneous slab) 모델로는 이 실측 시료를 제대로 설명하지 못한다. 문헌상 물에 팽윤된 폴리머 브러시는 흔히 **밀도 구배(graded refractive-index profile)** — 기판 쪽은 조밀하고 바깥쪽은 물에 가까워지는 구조 — 를 갖는 것으로 알려져 있다. 지금처럼 "두께 하나 + 굴절률 오프셋 하나"의 2-파라미터 모델은 이 구조를 표현할 정보가 부족해서, 옵티마이저가 물리적으로 말이 안 되는 경계값으로 도망치며 억지로 맞춘 것.

### 이게 왜 여전히 유의미한 결과인가

이 프로젝트 원문(§4, exp04)이 합성 데이터로 이미 보여준 명제 — **"모델이 틀리면 χ²가 좋아 보여도 결과는 틀린다"** — 를 이번엔 진짜 실측 데이터로 재확인한 셈이다. 다만 이번엔 잔차가 조용히 작게 나오며 결과만 슬쩍 틀리는 대신(exp04의 S1처럼), **옵티마이저가 물리적으로 불가능한 경계값(n≈1.0)으로 도망치는 형태로 "이 모델은 틀렸다"는 신호를 스스로 냈다** — 오히려 더 정직한 실패 모드였다.

## 5. 남은 과제 (다음에 이어서 할 만한 것)

1. **다층/구배 굴절률 모델**: PNIPAM 층을 여러 개의 얇은 sub-layer로 쪼개서 유효굴절률을 기판→표면 방향으로 단계적으로 바꾸는 모델 추가. `omf.core.coh_tmm`은 이미 임의 층수를 지원하므로 물리 엔진 자체는 손댈 필요 없음 — `EllipsometryModel`을 다중 sub-layer용으로 일반화하면 됨.
2. **더 단순한 실측 데이터셋으로 먼저 검증**: `refellips` 저장소에는 훨씬 단순한 데이터(`WVASE_example_2nmSiO2_11nmPNIPAM_658nm.txt` — 단일 파장 658nm, 4개 각도, 건조 또는 얇은 브러시)도 있음. 자유도 낮은 시료로 먼저 파이프라인을 검증한 뒤 복잡한 시료로 넘어가는 게 안전.
3. **SiO2 두께도 자유 파라미터화 고려**: 지금은 2nm으로 고정했는데, 실제 자연산화막 두께는 시료마다 다를 수 있음.
